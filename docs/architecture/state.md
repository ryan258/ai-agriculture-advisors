# State and recovery

- **Immutable saved records:** Chroma `query_history_v3`, schema 3, explicit inert embeddings and no embedding function. Old `query_history` is read without migration. Supported legacy records adapt in memory and are not rewritten on read.
- **Separate personal notes:** `personal_annotations` is created only on an explicit save. Title/status/next/last step/blocker/outcome/rating never rewrite generated content. Default exports omit notes.
- **Working state:** stdlib SQLite `workbench.sqlite3` inside the same configured directory stores runs, reusable starters/background, organization and import previews. JSON payloads are bounded; individual writes are transactional.
- **Checkpointing:** persist a run before dispatch and each in-flight receipt before its provider request. Persist each completed contribution and synthesis state. Graceful shutdown cancels local tasks and records interruption; a later process detects orphan active runs.
- **Manual recovery:** no status read schedules model work. Resume acknowledges in-flight/uncertain transport and obeys attempt/call/deadline bounds and provider wait. Successful entries are reused. A saved recovery version links to its immutable parent.
- **Idempotency:** generation submission keys identify one state; Save hashes its key and canonical result excluding timestamp. Same state returns the same ID; a changed checkpoint creates a distinct record. New unkeyed IDs are full UUIDs; legacy IDs remain readable.
- **Browser convenience:** panel preferences, question/task drafts, local per-result note drafts and last return ID. Plain JS can update controls and recover drafts; HTMX renders authoritative results. Only a confirmed matching note-save snapshot clears its draft. If browser storage fails, unsafe note navigation is blocked. Browser drafts are excluded from backups.
- **Metadata discovery:** scan old/new metadata in bounded batches, merge notes, cache complete rows, then filter/order/page. Save/annotation revision invalidates cache. Organization is read separately. Initial discovery remains proportional to metadata size; no answer bodies/embeddings are searched.
- **Additive import:** validate all preview rows first, then add; identical existing content keeps local notes, conflicting content gets a new ID. A storage failure can leave completed rows imported; retrying the preview does not overwrite them.

Keep state behind portable `lib` interfaces. Routes can select an operation but do not open databases directly. No browser event can elevate a local draft or client-supplied result into verified provider provenance. No provider/graph/test result constitutes personal outcome acceptance.
